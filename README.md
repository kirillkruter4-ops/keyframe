## Что это

Плеер, который играет почти всё без установки кодеков, использует GPU для
декодирования и при этом выглядит как продукт, а не как утилита из 2009 года.

Движок — [mpv](https://mpv.io) со встроенным FFmpeg. Интерфейс — свой,
на React, целиком поверх видео.

## Архитектура

```
┌──────────────────────────────────────────────┐
│ overlay window (Electron, transparent)        │  ← React UI
│   титлбар · таймлайн · панели · ⌘K            │
├──────────────────────────────────────────────┤
│ host window (Electron)                        │
│   └─ mpv child HWND (--wid, --vo=gpu-next)    │  ← видео, D3D11
└──────────────────────────────────────────────┘
        ▲
        │ JSON IPC через именованный канал
        ▼
    mpv.exe (отдельный процесс)
```

Три решения, которые стоит понимать до чтения кода:

1. **mpv запускается отдельным процессом, а не библиотекой.** Сегфолт в
   декодере убивает mpv, а не приложение: пользователь видит сообщение об
   ошибке, а не исчезнувшее окно.

2. **UI живёт в отдельном прозрачном окне.** Дочернее окно mpv рисуется поверх
   содержимого своего родителя, поэтому положить HTML на видео внутри одного
   окна невозможно. Следствие: над видео недоступен `backdrop-filter` —
   вместо размытия используются градиентные затемнения.

3. **DirectComposition в Chromium выключен** (`disable-direct-composition`).
   Без этого Chromium выводит содержимое через поверхность DWM, которая
   перекрывает все дочерние окна независимо от z-порядка, и видео не видно
   вообще.

## Разработка

Нужны Node 20+, [GitHub CLI](https://cli.github.com) и 7-Zip.

```bash
npm install
npm run fetch-mpv
npm run dev
```

`fetch-mpv` скачивает сборку mpv (~113 МБ) в `resources/mpv`. В репозитории
её нет намеренно.

Чтобы открыть файл сразу при запуске, без диалога:

```bash
$env:KEYFRAME_OPEN = "C:\path\to\video.mkv"; npm run dev
```

## Сборка установщика

```bash
npm run dist
```

Результат — `release/Keyframe-<версия>-setup.exe`, около 130 МБ (из них 113 МБ
приходится на mpv со всеми кодеками).

Если проект лежит в папке, которую индексирует Windows Search — например на
Рабочем столе, — сборка падает с `EBUSY` на `default_app.asar`: индексатор
открывает свежие файлы ровно тогда, когда electron-builder их удаляет. В этом
случае собирайте во временную папку:

```bash
npm run dist:local
```

## Проверка автообновления

Полный цикл можно прогнать локально, ничего не публикуя:

1. Соберите текущую версию, сохраните распакованную сборку в стороне
2. Поднимите версию в `package.json`, соберите ещё раз
3. Раздайте папку с новой сборкой: `python -m http.server 8099`
4. Запустите **старую** сборку, указав ей этот адрес:

```bash
$env:KEYFRAME_UPDATE_URL = "http://127.0.0.1:8099/"; $env:KEYFRAME_TEST_UPDATES = "1"; .\Keyframe.exe
```

Переменных нет в обычном запуске, поэтому канал обновлений остаётся тем,
что зашит при сборке.

## Релиз

Сборку и публикацию делает GitHub Actions по тегу:

```bash
git tag v0.1.0 && git push --tags
```

Установщик пока не подписан — Windows покажет предупреждение SmartScreen.
Подпись появится через SignPath Foundation, когда у проекта будет история.

## Что это

Плеер, который играет почти всё без установки кодеков, использует GPU для
декодирования и при этом выглядит как продукт, а не как утилита из 2009 года.

Движок — [mpv](https://mpv.io) со встроенным FFmpeg. Интерфейс — свой,
на React, целиком поверх видео.

## Управление

| Клавиша | Действие |
| --- | --- |
| `Space`, `K` | Пауза |
| `←` `→` | ±5 секунд |
| `J` `L` | ±10 секунд |
| `,` `.` | Кадр назад / вперёд |
| `[` `]` | Скорость по ступеням, `Backspace` — обычная |
| `↑` `↓`, колесо | Громкость, `M` — без звука |
| `V` | Субтитры вкл/выкл |
| `G` `H` | Субтитры раньше / позже на 0,1 с |
| `S` | Снимок кадра в «Изображения\Keyframe» |
| `I` | Сведения о файле |
| `N` `P` | Следующий / предыдущий файл списка |
| `F` | Полный экран, `Esc` — выйти |
| `Ctrl` + `O` | Открыть файл |
| `E` | Нарезать видео |

Правая кнопка мыши открывает меню со всем остальным: выбор дорожек звука и
субтитров, задержки звука и субтитров, пропорции кадра, скорость, повтор файла,
окно поверх остальных, снимок кадра и показ файла в проводнике. Пункты, у
которых есть сочетание клавиш, показывают его рядом.

Пока файл не открыт, клавиши и колесо ничего не делают: менять громкость там,
где нечего играть, — обещание, за которым ничего не стоит.

При наведении на таймлайн показывается кадр из этого места и время. Кадры
готовит отдельный mpv без вывода: просить их у того экземпляра, что показывает
фильм, нельзя — каждый переход сбивал бы воспроизведение. Кадр весит около
девяти килобайт и берётся по ключевым кадрам, поэтому появляется мгновенно;
уже показанные держатся в памяти, а вспомогательный процесс закрывается через
сорок пять секунд после того, как мышь ушла с дорожки.

Открыв файл, плеер подхватывает соседние из той же папки — «дальше» и «назад»
идут по ней в том же порядке, что в проводнике. Файлы `m3u` и `m3u8`
открываются как списки. Перетащить можно сразу несколько файлов: первый
заиграет, остальные встанут в очередь. Всё это отключается в настройках.

Плеер регистрируется в системной плашке Windows: название, кнопки паузы и
перемотки по списку, медиа-клавиши клавиатуры. Плашку рисует Windows по данным
mpv, поэтому подписана она именем mpv, а не Keyframe, — свой идентификатор
процессу mpv не передать. На превью окна в панели задач есть пауза и
перемотка, на иконке — полоска прогресса.

Громкость, размеры окна и позиция в фильме переживают перезапуск: состояние
лежит в `state.json` в папке приложения. Возврат к месту остановки предлагается
только для видео длиннее трёх минут и не у самого начала или конца.

Файл субтитров можно перетащить в окно поверх играющего видео — он подключится
к нему, а не заменит его.

## Нарезка видео

`E` — и нижняя треть окна становится дорожкой с кадрами. Картинка при этом не
закрывается: mpv умеет отдать часть своего окна под пустоту
(`video-margin-ratio-bottom`), и панель встаёт в неё, а не поверх кадра.

| Клавиша | Действие |
| --- | --- |
| `S` | Разрезать по плейхеду |
| `Del` | Удалить выбранное со сдвигом |
| `Ctrl` + `D` | Дублировать |
| `I` `O` | Отметить начало и конец момента |
| `Ctrl` + `X` | Вырезать отмеченное, `Ctrl` + `Shift` + `X` — оставить только его |
| `Ctrl` + `Z` | Отменить, `Ctrl` + `Shift` + `Z` — повторить |
| `Ctrl` + `R` | Вернуть весь файл целиком |
| `,` `.` | Кадр назад / вперёд |
| `Alt` + `←` `→` | По границам кусков |
| `Ctrl` + колесо, `+` `−` | Зум, `Shift` + `F` — вписать целиком |
| `Ctrl` + `S` | Сохранить нарезку |
| `Esc` | Выйти на ту же секунду фильма |

Мышью: тянуть за края куска — обрезать (с прилипанием к плейхеду и границам),
тянуть за середину — переставить, щелчок — выбрать и встать плейхедом, щелчок
по линейке — перемотка.

Результат монтажа виден сразу, без сборки и рендера. Пока редактор открыт, mpv
играет не файл, а склейку `edl://` из оставшихся кусков — тот же плеер, тот же
декодер, тот же GPU. Пересборка склейки после каждого реза стоит около десяти
миллисекунд и не растёт с числом кусков.

Сохранить можно **в новый файл** или **поверх исходного**. Поверх — через
временный файл рядом: mpv отпускает исходник, тот отходит под резервным именем,
на его место встаёт нарезка, и только потом резерв удаляется. Сорвалось на
середине — исходник возвращается на место.

Два способа резать. **Быстро** — потоки переписываются как есть, секунды на
файл любой длины, качество исходника не меняется, но резать можно только по
ключевым кадрам. Насколько именно уедет граница, написано в окне сохранения, а
на дорожке это место заштриховано; одной кнопкой резы переносятся на ключевые
кадры, чтобы превью совпало с файлом. **Точно** — перекодирование, режет ровно
там, где показано; на видеокарте (NVENC) в разы быстрее просмотра.

Для сохранения нужен `ffmpeg`. В установщик он не входит — это ещё восемьдесят
мегабайт поверх ста тринадцати у mpv, — поэтому ищется на машине, а если его
нет, скачивается при первом сохранении: около 45 МБ, один раз, с показом
прогресса.

Нарезка привязана к пути файла и переживает выход из редактора и перезапуск:
открыл тот же фильм — куски на месте. **Исходник не трогается никогда**, пока
об этом не попросят явно.

## Архитектура

```
┌──────────────────────────────────────────────┐
│ overlay window (Electron, transparent)        │  ← React UI
│   титлбар · таймлайн · панели · ⌘K            │
├──────────────────────────────────────────────┤
│ host window (Electron)                        │
│   └─ mpv child HWND (--wid, --vo=gpu-next)    │  ← видео, D3D11
└──────────────────────────────────────────────┘
        ▲
        │ JSON IPC через именованный канал
        ▼
    mpv.exe (отдельный процесс)
```

Три решения, которые стоит понимать до чтения кода:

1. **mpv запускается отдельным процессом, а не библиотекой.** Сегфолт в
   декодере убивает mpv, а не приложение: пользователь видит сообщение об
   ошибке, а не исчезнувшее окно.

2. **UI живёт в отдельном прозрачном окне.** Дочернее окно mpv рисуется поверх
   содержимого своего родителя, поэтому положить HTML на видео внутри одного
   окна невозможно. Следствие: над видео недоступен `backdrop-filter` —
   вместо размытия используются градиентные затемнения.

3. **DirectComposition в Chromium выключен** (`disable-direct-composition`).
   Без этого Chromium выводит содержимое через поверхность DWM, которая
   перекрывает все дочерние окна независимо от z-порядка, и видео не видно
   вообще.

## Разработка

Нужны Node 20+, [GitHub CLI](https://cli.github.com) и 7-Zip.

```bash
npm install
npm run fetch-mpv
npm run dev
```

Тесты покрывают модель нарезки: границы кусков, разрез, обрезку, удаление со
сдвигом, отмену и сборку команд ffmpeg. Всё это чистые функции без Electron и
React — ошибки на стыках кусков глазами не ловятся.

```bash
npm test
```

`fetch-mpv` скачивает сборку mpv (~113 МБ) в `resources/mpv`. В репозитории
её нет намеренно.

Иконки кнопок на превью в панели задач лежат в `resources/thumbar` и
пересобираются из тех же контуров, что и в интерфейсе:

```bash
npm run thumbar
```

Чтобы открыть файл сразу при запуске, без диалога:

```bash
$env:KEYFRAME_OPEN = "C:\path\to\video.mkv"; npm run dev
```

## Сборка установщика

```bash
npm run dist
```

Результат — `release/Keyframe-<версия>-setup.exe`, около 130 МБ (из них 113 МБ
приходится на mpv со всеми кодеками).

Если проект лежит в папке, которую индексирует Windows Search — например на
Рабочем столе, — сборка падает с `EBUSY` на `default_app.asar`: индексатор
открывает свежие файлы ровно тогда, когда electron-builder их удаляет. В этом
случае собирайте во временную папку:

```bash
npm run dist:local
```

## Проверка автообновления

Полный цикл можно прогнать локально, ничего не публикуя:

1. Соберите текущую версию, сохраните распакованную сборку в стороне
2. Поднимите версию в `package.json`, соберите ещё раз
3. Раздайте папку с новой сборкой: `python -m http.server 8099`
4. Запустите **старую** сборку, указав ей этот адрес:

```bash
$env:KEYFRAME_UPDATE_URL = "http://127.0.0.1:8099/"; $env:KEYFRAME_TEST_UPDATES = "1"; .\Keyframe.exe
```

Переменных нет в обычном запуске, поэтому канал обновлений остаётся тем,
что зашит при сборке.

## Релиз

Сборку и публикацию делает GitHub Actions по тегу:

```bash
git tag v0.1.0 && git push --tags
```

Установщик пока не подписан — Windows покажет предупреждение SmartScreen.
Подпись появится через SignPath Foundation, когда у проекта будет история.

Сборка подписывается сама, как только в окружении есть сертификат: правок в
конфигурации для этого не нужно. В GitHub Actions достаточно добавить секреты
`WINDOWS_CERTIFICATE` (файл `.pfx` в base64) и `WINDOWS_CERTIFICATE_PASSWORD` —
они попадают в `CSC_LINK` и `CSC_KEY_PASSWORD`, которые electron-builder читает
сам. Если сертификат задан, а подпись почему-то не получилась, релиз падает:
тихо неподписанная сборка опаснее явно неподписанной.

Локально то же самое:

```bash
$env:CSC_LINK = "C:\path\to\cert.pfx"; $env:CSC_KEY_PASSWORD = "..."; npm run dist
```
